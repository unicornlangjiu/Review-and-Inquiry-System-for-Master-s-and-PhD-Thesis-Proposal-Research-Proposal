# 硕博学位论文开题报告、RP审稿质询系统

> **版本：** v1.0
>**director by：** 博尔赫斯的舟舟
> **用途：** 面向硕博学位论文开题报告的全流程 AI 审稿质询系统
> **核心设计原则：** 以分审保深度，以合议保完整，以校验保连贯，以迭代保闭环

---

## 一、系统概述

本系统是一套由 **1 个主技能 + 7 个审核类子技能 + 2 个功能类子技能** 构成的 Agent Skills 协作体系，完成从文档接入到最终审稿结论的全流程闭环。

### 核心能力

- **七维度专项审核**：每个子技能独立聚焦开题报告的一个核心章节，确保审核深度不被稀释
- **跨章节逻辑校验**：系统性地排查章节之间的逻辑断裂（研究问题↔研究方法、研究背景↔研究创新点等）
- **分级质询机制**：致命问题强制回应、建议问题可选回应，完成从审核者到审稿人的视角转换
- **可迭代闭环**：支持最多 2 轮"质询→反馈→复审"循环，模拟真实审稿的多轮交互

### 最终目标

> 并非取代人类评审，而是为其提供一份**结构化、可追溯、有量化依据**的审稿底稿。

## 四、工作流程

### 七阶段主流程

```
┌─────────────────────────────────────────────────────────────────┐
│  阶段一：文档解析与章节映射                                       │
│  ─────────────────────────────────                              │
│  输入：用户提交的开题报告（.docx / .pdf / .md）                  │
│  输出：按章节拆分后的结构化内容                                  │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  阶段二：分项审核（并行执行）                                     │
│  ─────────────────────────────────                              │
│  7 个审核类子技能同时运行，各自输出：                            │
│  • 百分制评分 + 五档等级评定                                     │
│  • 结构化详细报告                                                │
│  • 致命/重要/建议 三级问题清单                                   │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  阶段三：跨部分逻辑一致性校验                                     │
│  ─────────────────────────────────                              │
│  6 组校验对：                                                    │
│  • 研究问题 ↔ 研究方法                                           │
│  • 研究背景 ↔ 研究创新点                                         │
│  • 研究方法 ↔ 研究计划                                           │
│  • 研究意义 ↔ 研究创新点                                         │
│  • 研究问题 ↔ 研究意义                                           │
│  • 研究计划 ↔ 研究创新点                                         │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  阶段四：报告整合                                                 │
│  ─────────────────────────────────                              │
│  4.1 问题总结报告（按严重程度排序）                              │
│  4.2 详细审核报告（按章节组合）                                  │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  阶段五：AI 质询生成                                              │
│  ─────────────────────────────────                              │
│  调用 AI_professor，将审核发现转化为分级质询：                   │
│  • 致命问题：标注【强制回应】                                    │
│  • 重要问题：标注【建议回应】                                    │
│  • 建议问题：标注【可选回应】                                    │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  阶段六：中间输出（存入 memory/）                                 │
│  ─────────────────────────────────                              │
│  • memory/问题总结.docx                                          │
│  • memory/详细报告.docx                                          │
│  • memory/质询报告.docx                                          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│  阶段七：反馈复审                                                 │
│  ─────────────────────────────────                              │
│  输入：用户反馈材料 + memory/ 中的前序文档                       │
│  调用 AI_review，输出：                                          │
│  • 四档结论：通过 / 修改后通过 / 修改后重审 / 不通过             │
│  • memory/复审意见(v1).docx / memory/复审意见(v2).docx           │
└─────────────────────────────────────────────────────────────────┘
                              ↓
                    ┌─────────────────┐
                    │   是否继续迭代？  │
                    └─────────────────┘
                          ↓ 是（未达2轮上限）
                    回到阶段五（新一轮质询）
                          ↓ 否
                    输出最终审稿意见
```

### 迭代闭环机制

- **最大迭代轮次**：2 轮
- **触发条件**：`conclusion = "修改后重审"` 且 `current_round < max_rounds`
- **状态传递**：第 N+1 轮质询自动继承前序上下文

## 六、使用指南

### 快速开始

1. **准备开题报告文档**：确保文档包含以下章节（标题关键词匹配）：
   - 论文题目 / 选题
   - 研究拟解决问题 / 研究问题 / 研究内容
   - 研究背景 / 课题背景 / 问题的提出
   - 研究计划 / 研究方案 / 技术路线
   - 研究方法 / 方法论
   - 研究意义 / 理论意义 / 实践意义
   - 创新点 / 创新性 / 特色与创新

2. **提交文档**：将文档提交给主技能 `main_thesis_review`

3. **等待审核完成**：系统自动完成七阶段流程，生成中间文档

4. **查看质询报告**：阅读 `memory/质询报告.docx`，按模板准备回应材料

5. **提交反馈**：按结构化格式提交回应材料，进入复审阶段

6. **查看复审意见**：阅读 `memory/复审意见(v1).docx`，根据结论决定是否需要新一轮迭代

### 用户反馈材料格式

```yaml
student_responses:
  - issue_id: "Q-01"
    student_response: "学生对质询Q-01的逐条回应..."
    evidence: "引用修改后的文本段落或新增内容..."
    
advisor_review:
  advisor_name: "导师姓名"
  overall_assessment: "导师对学生修改的总体评价..."
  specific_comments:
    - issue_id: "Q-01"
      advisor_comment: "导师对该条修改的意见..."
      advisor_stance: "同意 / 部分同意 / 不同意"
```

| | "开始审稿" | ✅ 自动执行全流程 |
| | "进行开题报告审核" | ✅ 自动执行全流程 |
| 显式触发 | "开题报告审稿" | ✅ 自动执行全流程 |
| | "论文质询" | ✅ 自动执行全流程 |
| | "学术评审" | ✅ 自动执行全流程 |

### 7.4 触发关键词匹配规则

系统通过以下规则识别用户意图：

1. **关键词匹配**：用户语句包含"审""稿""检查""评审""质询"等核心词时，自动关联开题报告审核流程
2. **上下文感知**：若用户已上传文件，优先执行全流程；若未上传文件，提示用户上传
3. **阶段识别**：根据当前系统状态（是否有 `memory/` 文档）判断用户意图是启动审核还是启动复审
4. **模糊匹配**：支持口语化表达，如"看看""帮我""怎么样"等非正式用语

## 八、评分体系

### 子技能评分权重

| 子技能 | 权重 | 说明 |
|--------|------|------|
| `research_title` | 0.18 | 题目是研究的第一印象 |
| `research_questions` | 0.18 | 研究问题是核心 |
| `research_background` | 0.15 | 背景支撑研究合理性 |
| `research_plan` | 0.12 | 计划体现可行性 |
| `research_method` | 0.12 | 方法是研究的路径 |
| `research_significance` | 0.10 | 意义体现价值 |
| `research_innovation` | 0.08 | 创新点是亮点 |
| 一致性校验 | 0.07 | 跨章节逻辑关联 |
| **合计** | **1.00** | — |

### 问题分级标准

| 级别 | 标识 | 说明 | 质询要求 |
|------|------|------|---------|
| 致命 | 🔴 | 动摇研究根基的致命缺陷 | 强制回应 |
| 重要 | 🟡 | 显著削弱论证质量 | 建议回应 |
| 建议 | 🟢 | 可提升空间 | 可选回应 |

### 复审结论四档

| 结论 | 条件 | 后续动作 |
|------|------|---------|
| **通过** | 致命问题全部解决，重要问题基本解决 | 流程结束 |
| **修改后通过** | 致命问题全部解决，重要问题部分解决 | 流程结束，建议参考遗留问题 |
| **修改后重审** | 致命问题未全部解决，且未达迭代上限 | 进入下一轮质询 |
| **不通过** | 致命问题未解决且已达迭代上限，或研究根基存在不可修复缺陷 | 流程结束，建议重新准备 |

## 八、学科适配说明

### 人文社科（默认模式）

- 执行完整的七步递进审查流程
- 启用批判性分析、理论对话、空白真实性五问等人文社科专属标准

### 理工科（通用模式）

- 自动检测并降级为通用模式
- 保留核心逻辑审查（聚焦漏斗、文献盘点、比重分析）
- 放宽人文社科专属要求（批判性分析→技术评价、空白真实性→技术缺口验证）
- 输出标注："学科适配声明"

## 九、注意事项

1. **文档格式**：支持 `.docx`、`.pdf`、`.md` 格式提交
2. **章节识别**：基于标题关键词匹配，建议使用中文章节标题
3. **迭代上限**：最多 2 轮质询-反馈-复审循环
4. **导师意见**：导师意见在复审中占有重要权重，当导师与 AI 评估冲突时进行说明并记录分歧
5. **存储空间**：`memory/` 文件夹会累积各轮次的文档，建议定期清理历史版本
